# 部署手册（docs/deploy.md）

> 微信售后服务平台 V3 · 阶段 0-5 部署指引（阶段 5：工单闭环与服务报告）

## 1. 前置条件

- 微信开发者工具（稳定版）
- 已注册小程序 AppID（云开发类型）
- 云开发环境（建议：`prod-xxx` 生产、`dev-xxx` 开发，两套环境隔离）

## 2. 目录说明

```

├─ miniprogram/            # 小程序前端（pages/components/utils）
├─ cloudfunctions/         # 云函数

│  ├─ login/               # login 云函数（含其私有 common 拷贝）
│  ├─ spare-parts/         # 备件主数据/批次/SN/商城目录（阶段 4）
```

## 3. 云函数部署步骤

1. 在 `cloudfunctions/login/package.json` 确认依赖：`wx-server-sdk`、`jsonwebtoken`（如需 JWT，可选）、`lodash`（可选）。
2. 公共模块分发：`login` 使用 `cloudfunctions/login/common`（部署时随函数一并上传，代码 `require('./common/authGuard')`）。多函数共享时按项目书约定同步更新（可加 scripts/sync-common.py 后续版本）。
3. 开发者工具 → 云开发控制台 → 创建环境，记录环境 ID。
4. 对 `login` 右键「上传并部署：云端安装依赖」。
5. 控制台新建集合：users、device_profiles、engineer_schedules、appointments、spare_parts、stock_batches、inventory_flows、orders、carts（阶段 4 新增）、waybills、work_orders、work_steps、notifications、reports、evaluations、visit_plans、knowledge_base、system_config、audit_logs、payment_flows、token_blacklist、upload_logs、export_records（阶段7 新增，23 集合，与 schema.md 一致）。
6. 按 database-security.md 配置每集合安全规则；按 schema.md 建索引（重点：orders.order_no 唯一、orders._openid+status、stock_batches.part_id+batch_no 唯一、carts._openid+part_id 唯一、payment_flows.transaction_id 唯一、payment_flows.nonce 唯一）。
7. 阶段 4 云函数（spare-parts / inventory / order / pay / invoice）逐个右键「上传并部署：云端安装依赖」，并将 `cloudfunctions/common` 同步到各函数私有 common 目录（部署后立即生效）。
8. **阶段 5 云函数**（work-orders / upload / accept / report / statemachine）逐个右键「上传并部署：云端安装依赖」。其中 `report` 依赖 `pdfkit`（已在 package.json 声明，云端安装）；`upload` 需在云开发控制台为该函数开启 `security.msgSecCheck` / `security.imgSecCheck` 开放能力（config.json 已声明，控制台仍需授权）。
9. 阶段 5 完成后建议运行 `scripts/scan_secrets.py` 与 `scripts/validate_schema.py` 复验安全红线；`scripts/verify_stage5.py` 做静态自检（见 6.4）。
10. **阶段 7 云函数**（dashboard / cost-stats / export）逐个右键「上传并部署：云端安装依赖」。其中 `export` 依赖 `xlsx`（已在 package.json 声明，云端安装）；导出文件写入私有读容器 `exports/`，控制台确保该容器禁止客户端直读。
11. **阶段 8 云函数**（evaluation / knowledge）逐个右键「上传并部署：云端安装依赖」。`evaluation` 依赖无新增（限流/审计走 common）；`knowledge` 无新增依赖；两者均使用私有 common，务必与 `cloudfunctions/common` 保持同步。

## 4. 环境变量配置（云函数环境变量）

参考 `docs/env-template.md`。在云开发控制台「云函数 → 配置 → 环境变量」逐项注入，**不要**写死在代码里。

## 5. 小程序端配置

- `miniprogram/app.js` 中 `cloud.init({ env: '<环境ID>' })`，上线前替换为生产环境 ID。
- 页面路径已登记在 `app.json`；若新增页面需同步更新。
- 本地调试建议使用「云开发本地调试」直连云函数。

## 5.5 阶段 4：微信支付 API v3 部署补充

### 5.5.1 启用前置
1. 在微信支付商户平台开通「JSAPI 支付」，完成商户号与小程序 AppID 绑定。
2. 按 `docs/env-template.md` 第 2 节注入 7 个 `PAY_*` 环境变量（pay 云函数 → 配置 → 环境变量）。
3. 私钥/证书处理：商户 API 私钥与微信支付平台证书均以 PEM 文本注入（`\n` 用真实换行），**严禁**提交仓库或写入前端。

### 5.5.2 回调接入（pay/callback）
1. 给 `pay` 云函数开启 **HTTP 访问服务（HTTPS 触发）**，路径映射为 `/callback`。
2. 将得到的完整回调 URL 填入 `PAY_NOTIFY_URL` 环境变量。
3. 回调校验顺序（代码已固化）：① 头完整性 → ② 时间窗 ≤5 分钟（防重放）→ ③ 平台证书验签 → ④ AES-256-GCM 解密 → ⑤ nonce 去重（payment_flows.nonce 唯一）→ ⑥ 订单状态机幂等（仅 pending 可入账）→ ⑦ 事务更新订单 + 支付流水 → 返回 `200`。任一校验失败返回非 2xx（微信将重试，靠幂等保证不重复入账）。

### 5.5.3 主动查单补单
- `pay.query` 支持对 pending 订单主动调微信查单并补单。
- 生产建议在云开发控制台为 `pay` 配置定时触发器：支付后 5 / 30 / 120 / 1440 分钟各触发一次 `pay.query`（可加 `--` 参数区分档位；触发器 JSON 示例见项目书），兜底回调丢失场景。

### 5.5.4 T+1 对账
- 每日从微信支付商户平台下载前一日交易账单（微信支付对账单，仅需商户号，可用 `pay` 云函数或脚本获取）。
- 对账逻辑：账单金额 vs `payment_flows.amount_fen` + `orders.pay_fen`，差异项人工复核；`scripts/stock_reconcile.py` 负责库存流水与批次账面兜底对账（见 6.3）。

## 6. 联调与验收

- 运行 `scripts/validate_schema.py`：确认 schema.md 覆盖 20 集合（+ carts 等增量集合）且权限归属无全开。
- 运行 `scripts/scan_secrets.py`：确认无密钥残留（白名单项除外）。
- 登录链路：login 云函数 → authGuard 校验 → 返回统一响应。
- i18n：切换语言后 t(key) 取词、wx.setStorageSync 持久化、页面文案即时生效。
- 阶段 4 关键链路：备件管理（spare-parts）→ 入库批次（batch.create 事务）→ 商城下单（order.create 事务防超卖）→ 支付（pay.create/callback）→ 发货/完成（order.ship/complete）→ 发票（invoice.request/issue）。
- 库存对账兜底：`python scripts/stock_reconcile.py --demo` 应输出 `OK: 账实一致`；接入真实数据用 `--flows` / `--batches` 参数。
- **阶段 5 关键链路**：工单创建（work-orders.wo.create，预约已批准→初始化 work_steps）→ 进度追加（wo.progress，带 audit_logs）→ 状态流转（statemachine.wo.transition，不可跳级）→ 客户验收/驳回（accept.wo.accept / wo.reject，openid 匹配）→ 服务报告（report.generate PDF 私有读）→ 闭环（wo.transition→closed）。
- **阶段 5 安全验收**：① 状态机非法流转（如 pending→pending_acceptance、closed→processing）必须返回 `INVALID_TRANSITION`；② 非关联客户验收他人工单必须返回 `NOT_WO_OWNER`/`WO_NOT_ACCESSIBLE`；③ 伪装扩展名/超 5MB/内容不安全上传必须被拒绝并清理文件；④ 进度追加必须产生 audit_logs；⑤ PDF 报告要素（设备/工单/方案/结果/双签）齐全且仅私有读。


## 6.5 阶段 6：物流追踪与订阅消息

### 部署云函数

| 云函数 | 职责 | 部署注意 |
|---|---|---|
| `logistics` | 快递100 统一调用层（logisticsClient.js）、发货建单、轨迹查询、回调验签与订单联动 | config.json 声明 HTTPS 触发器（回调地址 `<env>-xxx.cloudfunctions.net/logistics/callback`） |
| `subscribe` | 订阅消息模板列表、授权登记、服务端发送（openapi subscribeMessage.send） | config.json 声明 openapi 权限 `subscribeMessage.send`；模板 ID 仅存环境变量 |
| `cron` | 定时触发器：保养提醒 / 库存预警 / 支付对账 / 报告清理 | config.json 已含 4 个 timer 触发器（cronMaintenance 每日 9 点 / cronStockAlert 8 点 / cronPayReconcile 3:30 / cronReportCleanup 4 点） |

### 前置开通

1. 快递100：注册开通「物流查询」服务，取得 `EXPRESS_API_KEY` 与 `EXPRESS_CUSTOMER`；在快递100后台配置回调地址 `https://<env>-xxx.cloudfunctions.net/logistics/callback`，回调验签密钥为 `KUAIDI100_KEY` / `KUAIDI100_CUSTOMER`（MD5(body+key+customer)，需与云函数环境变量一致）。
2. 微信订阅消息：小程序后台申请 6 个订阅模板（预约通过/上门提醒/工单进度/物流动态/库存预警/保养提醒），将模板 ID 注入 `SUB_TMPL_*` 环境变量。
3. 订阅发送内部密钥 `SUBSCRIBE_INTERNAL_KEY`：云函数间调用 subscribe.send 的服务端凭证（statemachine/logistics/cron 均通过该密钥触发订阅推送，前端零密钥）。

### 联调与验收

- 运行 `scripts/verify_stage6.py`：覆盖状态流转、订阅权限与发送、物流追踪查询、越权与安全红线回归、语言包一致性、语法检查。
- 关键链路：商城订单发货（logistics.create，建 waybill + 快递100 订阅 + 站内通知）→ 物流状态流转（logistics.callback 验签后 pending→in_transit→delivered，订单 status 联动 shipped→completed）→ 客户物流追踪（logistics.list / trace，openid 行级隔离）→ 订阅管理（subscribe.templates / allow / list）→ 工单进度订阅（statemachine 流转触发 subscribe.send）→ 定时任务（cron 四触发器写 notifications + 订阅推送）。
- 安全验收：① 回调验签失败必须返回 401 且不落库；② 非本人运单查询返回 `WAYBILL_NOT_ACCESSIBLE`；③ subscribe.send 无内部密钥且非 admin 必须拒绝；④ 未授权模板发送返回 `NOT_SUBSCRIBED`；⑤ 日志与审计对 openid 脱敏；⑥ 定时任务仅归档标记不物理删除。

## 6.7 阶段 7：数据看板 / 成本统计 / Excel 导出

### 部署云函数

| 云函数 | 职责 | 部署注意 |
|---|---|---|
| `dashboard` | 看板聚合：工单状态分布、预约、低库存、成本汇总、近 N 天趋势 | 只读聚合，无新增密钥 |
| `cost-stats` | 成本统计：汇总/月度趋势/构成/TOP10；成本参数 config.read/write | 参数默认值由 `system_config.cost.*` 初始化，仅 admin 可写 |
| `export` | Excel 导出（SheetJS）：create 生成 xlsx → 私有读容器 → get/list 临时链接与归属校验 | package.json 依赖 `xlsx`，云端安装 |

### 联调与验收

- 运行 `scripts/verify_stage7.py`：覆盖看板数据聚合正确性、成本统计口径、Excel 导出权限与文件访问控制、越权与安全红线回归、语言包一致性、语法检查。
- 关键链路：看板（dashboard.overview 按角色裁剪，客户不含成本/库存）→ 成本统计（cost.stats.read 按 accepted/closed 口径，cost.config 仅 admin 写）→ 报表导出（export.create 校验 EXPORT_CREATE → 私有读容器写入 → export.get 归属 + 过期校验 → 临时链接下载，前端 wx.downloadFile + openDocument 预览）。
- 安全验收：① 客户调用 `dashboard.overview` 返回不含 `cost/low_stock` 内部指标；② 非 admin 调 `cost.config.write` 必须返回 `FORBIDDEN`；③ 导出他人工单/调用他人导出记录必须返回 `EXPORT_NOT_OWNER`/`WO_NOT_ACCESSIBLE`；④ 过期导出链接拒绝返回；⑤ 前端零密钥（无 xlsx、无存储路径硬编码）。


## 6.8 阶段 8：服务评价与知识库

### 部署云函数

| 云函数 | 职责 | 部署注意 |
|---|---|---|
| `evaluation` | 服务评价提交（eval.create，工单客户本人 + accepted/closed 可评 + 唯一防重复）、列表（eval.list 按角色行级隔离）、满意度统计（eval.stats 内部角色；工程师仅本人被评）、回访计划（visit.create/list/record，owner/admin 管理） | 提交接口限流（滑动窗口 10 次/人）；common 同步 |
| `knowledge` | 知识库文章管理：list/detail/create/update/delete/from_wo（工单沉淀案例）；public/internal 两级可见隔离 | 无新增密钥；common 同步 |

### 联调与验收
